# X-RAG 英文帖子中文翻译设计

## 目标

为英文 X 帖子附加机器生成的中文译文，同时永久保留英文原文。译文应进入权威 Markdown、RAG 索引和公开热点看板；现有帖子可一次性补译，之后采集和导入的新帖子自动翻译。整个流程仅使用本地模型，不把帖子正文发送到云端，也不删除既有 Markdown、媒体或电脑中的其他文件。

## 用户体验

- Markdown 按“英文原文、中文翻译、媒体、引用帖、原帖链接”的顺序展示。中文翻译带有“机器翻译”标识。
- 英文引用帖也附加中文译文；中文或以中文为主的主帖、引用帖不生成多余译文。
- 看板卡片优先展示中文译文并标注“机器翻译”。详情窗口分开显示完整中文译文和英文原文。
- 缺少译文时，Markdown、RAG 和看板均安全回退到原文，不显示空白翻译区域。
- RAG 同时索引原文和译文，因此中文查询可以召回英文帖子，英文查询仍可命中原文。

## 本地模型

采用 `Helsinki-NLP/opus-mt-en-zh` 专用英中翻译模型，通过项目已有的 `transformers` 与 `torch` 栈运行。安装流程解析并记录模型快照 revision 与文件 SHA-256；日常任务只加载已校验的本地快照，不联网寻找新版本。

模型保存在项目的 Git 忽略目录 `data/models/translation/`。安装命令只在该目录创建模型文件及清单，不读取或改写帖子。模型下载完成并逐文件校验后才原子发布为可用快照；失败时不会把半成品当作可用模型。清理仅限本次安装创建且经过精确路径验证的临时目录，不遍历或删除其他目录。

运行时使用 CPU 和确定性推理设置。模型仅接收需要翻译的公开帖子文本，不接收认证信息、日志或本地路径。

## 数据模型与 Markdown 格式

`Post` 和 `QuotedPost` 新增可选的中文译文字段。主帖另保存翻译元数据：

- 目标语言：`zh-CN`
- 模型 ID 与本地快照 revision
- 英文源文本的 SHA-256
- 翻译时间

引用帖保存等价的翻译元数据。源文本哈希用于判断译文能否复用：哈希、目标语言和模型快照均匹配时不重新翻译；任一项变化时重新生成。

主帖的英文正文继续使用现有 `xrag:text` 标记，保证旧读取逻辑和原文提取稳定。中文译文使用独立的 `xrag:text-zh` 起止标记，并在 Markdown 正文中显示为“中文翻译（机器翻译）”小节。读取器接受没有翻译字段的旧版 Markdown；写入器只增加可选翻译数据，不改变帖子 ID、原文、媒体路径或原始 X URL。

翻译元数据属于本地权威存档。公开看板只输出展示所需的 `text_zh`，不公开本地模型路径、内部哈希或翻译缓存信息。

## 语言判断与文本保护

判断前临时排除 URL、用户名、标签、代币符号和代码片段。剩余文字至少包含 15 个拉丁字母，且拉丁字母占全部拉丁/CJK 字符的 60% 以上时，视为需要英译中。这样可以跳过中文正文中偶尔出现的 `AI`、`RWA` 等英文术语，同时覆盖以英文为主的混合帖子。

翻译前保护以下内容：

- HTTPS URL
- `@用户名`、`#标签`、`$代币`
- 反引号代码片段
- 术语表中的 AI/Web3 固定写法，例如 `AI Agent`、`AGI`、`RWA`、`x402`、`Solana`、`MiCA`、`CLARITY Act`

受保护片段以可验证占位符参与推理。翻译后必须逐个、按次数无损恢复；若占位符缺失、重复或次序异常，则该条翻译失败并保留原文，不写入不可信译文。译文还需通过已有公开内容安全扫描，防止把凭据形式或本地路径带入公开快照。

## 组件边界

新增独立翻译模块，职责分为四层：

1. `LanguageDetector`：纯函数判断文本是否需要英译中。
2. `TextProtector`：保护并严格恢复 URL、账号、标签、代码和术语。
3. `LocalTranslator`：从已校验的本地模型清单加载固定快照并进行批量推理。
4. `TranslationEnricher`：根据源哈希复用译文，分别处理主帖和引用帖，返回新的不可变 `Post`。

采集服务、导入服务、补译命令只依赖 `TranslationEnricher` 接口。测试可以注入确定性的轻量假翻译器，不需要下载真实模型；真实模型另做离线 smoke test。Markdown 存储、向量索引和看板导出不直接依赖 `torch` 或模型加载逻辑。

## 数据流

### 新采集或导入

1. OpenCLI 或导入器生成原始 `Post`。
2. 媒体归档完成后，翻译增强器检查现有同 ID Markdown。
3. 若英文源文本及模型信息未变化，复用已有译文；否则在本地生成译文。
4. Markdown 以原子替换方式写入双语内容。
5. 向量索引使用“英文原文 + 中文译文 + 引用原文 + 引用译文”的可搜索文本。
6. 看板构建并发布双语字段。

### 现有内容补译

新增命令组：

```text
xrag --root . translation install
xrag --root . translation backfill
```

`translation install` 下载并验证模型，不触碰帖子。`translation backfill` 在写锁下扫描全部权威 Markdown，只更新需要新增或刷新译文的帖子；每个文件独立原子写入。全部扫描结束后使用现有的 staging/swap 机制原子重建 RAG 索引。命令报告 `scanned`、`translated`、`reused`、`skipped` 和 `errors` 数量。

补译前记录现有权威 Markdown 与媒体清单。补译后必须证明旧路径缺失数为零；任何错误都不得通过删除源文件来恢复。

### 每日任务

每日 10:00 的顺序为：采集四组关键词、翻译或复用译文、写入 Markdown 与 RAG、构建双语看板、校验、通过 Windows Git 发布。计划任务不自动下载或升级模型；模型缺失或清单校验失败时，在写入采集结果前失败关闭，保留当前线上快照。

## 错误处理

- 整个模型不可用、模型清单损坏或哈希不匹配：在数据写入前停止本次采集/补译，输出脱敏错误，不发布。
- 单条语言判断、推理或占位符恢复失败：保留原文，不写入该条译文，记录脱敏错误并继续其他帖子；命令最终报告错误数。
- 单个 Markdown 写入失败：原文件保持不变，其他文件不被删除。
- RAG 重建失败：现有稳定索引保持可用；已安全写入的 Markdown 仍是权威数据，可在修复后重新运行补译或重建。
- 看板构建或发布失败：已有 GitHub Pages 快照保持不变。

错误日志不得记录完整帖子正文、译文、模型下载 URL 中的凭据参数或本地绝对路径。失败重试依赖源哈希和模型 revision，已成功译文不会重复计算。

## 看板契约与界面

公开帖子对象新增可选字符串 `text_zh`。前端校验器接受缺失或非空的安全译文，但拒绝空白译文、非字符串值和包含不安全公开内容的快照。其他统计、主题、媒体和 URL 契约保持不变。

主视觉和普通卡片在 `text_zh` 存在时使用中文摘要，并显示“机器翻译”标签；否则使用 `text`。详情窗口按中文在前、英文在后的顺序展示，使用明确标题和独立文本节点，避免把正文当 HTML 注入。移动端两个区域自然纵向排列，不增加横向滚动。

“立即刷新”仍只重新读取已发布快照，不触发本机翻译或采集。

## 测试策略

严格采用测试先行：每个新行为先观察到针对缺失功能的失败，再实现最小代码。

- 单元测试：英文判定边界、中英混合文本、术语/URL/账号保护、占位符损坏、源哈希复用、模型清单校验。
- Markdown 测试：旧格式兼容、双语往返、引用帖译文、原文完全不变、原子失败保留旧文件。
- 服务测试：采集和导入自动翻译、模型缺失时零数据写入、单条失败继续并计数。
- RAG 测试：中文查询命中英文帖，英文查询仍命中原文，失败重建保留稳定索引。
- 导出与前端测试：`text_zh` 白名单与验证、卡片中文优先、详情双语、无译文回退、文本节点防注入、响应式布局。
- CLI 与计划任务测试：安装、补译、每日顺序、模型只离线加载、发布失败保留线上快照。
- 真实 smoke test：本地模型对固定英文 AI/Web3 样例生成非空中文，保护片段逐字保留；该测试不把正文发送到网络。
- 非删除验收：补译前后的既有 Markdown/媒体路径集合比较，要求缺失数为零。

最终交付前重新运行完整 Python 测试、Node 前端测试、脚本语法检查、Git diff 检查，并在人工批准模型下载后执行一次现有内容补译与真实计划任务发布验收。

## 非目标

- 不生成帖子摘要、事实核查或观点改写。
- 不翻译图片中的文字、视频或外部网页。
- 不调用收费或云端翻译 API。
- 不自动升级模型，也不自动删除旧模型、历史 JSON、媒体或帖子。
- 不改变“原始 Markdown 是权威数据、Chroma 可重建”的现有原则。
